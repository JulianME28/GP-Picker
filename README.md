# GP-Picker

Google Apps Script для автоматичного підбору донорів ГП під проєкт.

Скрипт читає рядок проєкту в таблиці пирогів, підбирає донорів із бази
«Топ (Робоч)» і записує їх окремим листом «Донори» у файл ТЗ замовника,
посилання на який стоїть у колонці F того ж рядка.

## Файли

| Файл | Призначення |
|---|---|
| `pidbir_donoriv.gs` | сам скрипт; у проєкті Apps Script лежить як «Підбір ГП.gs» |
| `check_logic.py` | перевірка логіки на CSV-дампах бази й листа проєктів |

## Що бере з рядка проєкту

| Колонка | Значення |
|---|---|
| C | назва проєкту — з неї визначається ГЕО (`Non Aams IT` → `IT`) |
| D | скільки донорів треба по ТЗ |
| E | мова проєкту |
| F | посилання на файл ТЗ замовника — саме туди пишеться результат |

Після вдалого підбору проставляє H (Публікація) → «Погоджено донорів»
і S (Простір) → «на тул».

## Логіка підбору

Донори розкладаються по чергах; усередині черги — сортування за трафіком
спадно. Один донор потрапляє лише в одну чергу.

1. **Мова проєкту + ГЕО проєкту** — найточніше влучання
2. **Уся мова проєкту** — решта донорів цією мовою
3. **Увесь домашній регіон** — усі донори, чиє ГЕО належить регіону проєкту
4. **Англомовні** — English із регіонів, доречних для проєкту

Черги 1–2 позначені `native`: вони беруться з **усієї бази**, без порогів
DR/трафіку і без фільтра регіонів. Донора рідною мовою беремо в будь-якому
разі — на дрібних мовних ринках їх одиниці. Черги 3–4 — тільки ті, хто
проходить пороги.

### Регіон визначається за ГЕО, а не за блоком бази

Блоки в базі заповнені непослідовно: єдиний `nz`-донор лежить у блоці
«Бразилія», `ru` і `vn` — в «Арабських», `kr` — в «Америці». Тому регіон
рахується з ГЕО (`GP_REGION_GEO`), а мова потрібна лише як запасний варіант,
коли ГЕО з назви проєкту вийняти не вдалось.

Для англомовних проєктів це критично: `Online Casinos NZ` — це Океанія,
а не Америка, тож австралійські донори йдуть першими.

Регіони: Європа, Америка, Океанія, ЛатАм, Бразилія, Індія, Азія,
Арабські, Африка. Які регіони допустимі для якого проєкту — `GP_REGION_ALLOW`.

### Пороги

- DR — від 10, нижче не беремо взагалі
- трафік — від 100 (орієнтир 150)
- для англомовних донорів трафік — від 50

Донори з блоків «Тір 2» і «Тір 3» у черги 3–4 не потрапляють ніколи.
Зайти можуть лише тоді, коли їх вимагає сама мова або ГЕО проєкту.
Це єдине місце, де досі використовується блок, а не ГЕО — бо в базі
це саме позначка блоку.

Жовтим у листі «Донори» підсвічені рядки, де донор пройшов лише завдяки
мові/ГЕО, всупереч порогам.

## Встановлення

1. Таблиця пирогів → **Розширення → Apps Script**
2. Створити файл «Підбір ГП.gs», вставити вміст `pidbir_donoriv.gs`
3. У `GP_BASE_ID` підставити ID своєї таблиці-бази донорів
4. Один раз запустити функцію `GP_install` — вона створить тригер меню
5. Перезавантажити таблицю — з'явиться меню «Підбір ГП»

Меню навмисно вішається інстальованим тригером (`GP_install` → `GP_showMenu`),
а не через `onOpen`: у проєкті вже є чужі скрипти, і `onOpen` зайнятий.

## Перевірка логіки

`check_logic.py` читає константи **прямо з `.gs`** — тобто перевіряє справжній
код, а не свою копію. Ловить коди країн, що випали з мапи регіонів, регіони
без `GP_REGION_ALLOW` і мови, що вказують на неіснуючий регіон.

Потрібні два CSV-експорти (База «Топ (Робоч)» і лист проєктів) — шляхи до них
задані вгорі файлу. Запускати після кожної правки таблиць регіонів.
